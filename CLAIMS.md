# Claims traceability

Maps the factory's normative claims (the invariants in
[`safety-contract.md`](safety-contract.md) and the behaviour described in
[`README.md`](README.md)) to the tests that enforce them. **Enforced** = a real test exists and `make verify` runs it.
**Partial** = some of the claim is enforced, some isn't — see [Remaining gaps](#remaining-gaps).

`internal/claims` mechanically checks that every `Test*` name below actually
exists in the repo; it cannot check that the test still covers the claim
faithfully — that stays a human/review judgment.

This file is the current-state summary. The round-by-round history of
reviews, bugs and fixes is kept outside this repo.

## Remaining gaps

Real, currently-open gaps.

- **The Temporal-path scenario suite (`TestParityDirectAndTemporalPaths`)
  does not cover `reference_oracle` pass/fail/tamper, or a
  real-engine/live-Docker run.** `reference_oracle` pass/fail has its own
  end-to-end coverage (the runtime-canary row above,
  `integration_oracle_named_gates_test.go`,
  `integration_oracle_in_loop_test.go`); adding it to this suite means
  threading the canary's Docker wrapper through
  `testsuite.WorkflowTestSuite`.
- **Two Temporal hard-termination tests are an accepted load-sensitive
  flake class.** `TestIntegrationTemporalCancelsOrphanedWorkflowOnTimeout`
  and `TestIntegrationIsolateWorkspaceRollsBackOnHardTerminationViaTemporal`
  pass standalone; a very-delayed failure under sustained shared-server
  load is accepted, not treated as a production timeout change.
- **Containment / sandboxing.** Partial. Current status, boundary by
  boundary, lives in [`containment-matrix.md`](containment-matrix.md).
  Open residuals, both needing daemon-level `userns-remap` to close: the
  group-write grant on the worktree widens access to any process sharing
  factoryd's GID, and host-visible UID attribution depends on the Docker
  backend's bind-mount behavior (works on native Linux, not colima's
  shared-folder mount).
- **Crash-durability edge case.** A `save()` failure that happens mid-run
  (e.g. disk fills between two saves) cannot be durably recorded:
  persistence itself is what broke. Accepted as structurally unfixable
  in-process.
- **A very-delayed, very-quiet reconciliation race.** If an original
  `SignalWithStartWorkflow` is still unsettled after a repository's owner
  has been idle for 24h (`IdleTimeout`) and receives no other work, a fresh
  owner execution could dispatch that stale request with no memory of an
  earlier cancellation. Not chased: closing it needs changing the owner's
  idle-completion determinism.
- **No merge/deploy side effect is wired to a release decision.** By
  design (SC-001): nothing acts on an `Allowed` decision toward a merge or
  deploy, and the release screen exposes no kill-switch control
  (CLI-only, so the last-resort stop never depends on a healthy `factoryd
  serve`). Recording a decision is best-effort, not fail-closed: it runs
  after the run's terminal state is saved, so a recording failure logs a
  warning and leaves the failure marker (row above) instead of
  quarantining the run.
- **Workspace isolation: a stranded worktree.** A SIGKILL, panic or power
  loss between the worktree being created and the next durable save can
  strand a worktree and branch; ownership markers permit conservative
  reconciliation under the exclusive repository lock, and inconclusive
  evidence leaks safely.
- **`full_suite_verify`'s cross-run attribution is not a bisected root
  cause.** It blames the immediate declared predecessor; the regression
  could equally be this run's own change interacting with it. Every-N
  cadence is opt-in.
- **The checkpoint after the first ticket of a pilot is intentionally
  human.** Not an undecided implementation gap.
