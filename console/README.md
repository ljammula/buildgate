# Buildgate console (React + TypeScript)

The operator console of `factoryd`: a static bundle built here and embedded in
the binary (`internal/consoleweb`), served from the same origin as the API.
It needs Node 20+ and npm.

## Commands

```sh
npm ci                 # install (scripts are disabled by .npmrc)
npm run check          # typecheck, lint, format check, tests: the bar for every change
npm run test -- src/domain/status.test.ts   # one file
npm run dev            # dev server; set VITE_API_BASE_URL to a running factoryd
npm run build          # static bundle in dist/
test/walk/run.sh       # the live walk: a real factoryd, a real browser, every screen and action
```

| From the repository root | What it does                                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `make console-test`      | `npm ci && npm run check`                                                                                  |
| `make console-build`     | Builds the bundle and embeds it (`internal/consoleweb/dist`); the next `go build ./cmd/factoryd` serves it |
| `make console-walk`      | `test/walk/run.sh`: the live walk below                                                                    |

## Checks, and what each one is for

| Check                    | Run                                                                            | Catches                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unit and component tests | `npm run test`                                                                 | Logic and rendering, in isolation, against a fake server (`src/test/render.tsx`)                                                                                                                                                                                                                                                                            |
| Contract fixtures        | `go test ./internal/api -run TestConsoleContractFixtures`, then `npm run test` | A Go response shape the decoders cannot read                                                                                                                                                                                                                                                                                                                |
| Golden vectors           | The Go and Vitest suites                                                       | The server and the console disagreeing on a content hash, a token count or a spec/ticket structure check                                                                                                                                                                                                                                                    |
| Lint boundaries          | `npm run lint`                                                                 | A layer importing what it may not; HTML from untrusted text; `fetch` or `localStorage` in the wrong layer                                                                                                                                                                                                                                                   |
| Live walk                | `test/walk/run.sh`                                                             | What only a real server and browser show: 43 steps, each write checked against the server's own record                                                                                                                                                                                                                                                      |
| Theme tokens             | `npm run test` (`src/app/tokens.test.ts`)                                      | A token pair below its contrast bar; the pairs that miss today are listed in the test and only shrink                                                                                                                                                                                                                                                       |
| Screenshots              | `WALK_SCRIPT=shots.mjs test/walk/run.sh`                                       | Every screen in both themes; `WALK_VIEWPORTS=1440x900,960x900` photographs several sizes (file names gain the width). `WALK_SEED=demo` is the dense seed with a live worker and a release policy set: `demo/mission-control-*.png` are `/?days=all` photographed with it                                                                                    |
| Links                    | `WALK_SCRIPT=links.mjs test/walk/run.sh`                                       | A link that leads nowhere: every link of every screen is clicked, with each tab, filter chip, view toggle and list row pressed to find more, and the screen it lands on must draw with no failed read and draw the same after a reload. It presses nothing that writes, so `links.mjs` can also be pointed at a console in use (its header has the command) |
| Phone                    | `WALK_SCRIPT=phone.mjs WALK_SEED=dense test/walk/run.sh`                       | A screen that does not fit a phone: wider than the screen, content cut off at the right edge outside a box that scrolls, a navigation taller than a quarter of the screen, a title squeezed out. Photographs every screen at that size                                                                                                                      |
| Board layout             | `WALK_SCRIPT=layout.mjs WALK_SEED=dense test/walk/run.sh`                      | Board start height, visible title length and unintended sideways overflow against fixed bars; exits 1 on a miss, and passes on the dense seed. `WALK_SEED=dense` adds twenty requests in two projects                                                                                                                                                       |

`scripts/console-walk/run.sh` (repository root) is the second walk: one real request through drafting, review and a build against a model route, driven only from the console (it needs Docker, the OpenShell gateway and Temporal; its header lists them).

`WALK_SCRIPT=record.mjs test/walk/run.sh` records a captioned tour of the console against the same seeded server (`<walk-dir>/recording/console-tour.webm`). It rewrites home-directory paths in the page before they are painted and fails if one is still visible, so the recording can be published as it is. `demo/console-tour.mp4`, the one copy kept in the repository because H.264 plays in every browser, is that file converted with `ffmpeg -i console-tour.webm -c:v libx264 -preset slow -crf 26 -pix_fmt yuv420p -movflags +faststart -an -map_metadata -1 console-tour.mp4`.

`npx playwright install chromium` once before the walk; `WALK_BROWSER_CHANNEL=chrome` uses an installed Google Chrome instead.

## Add a screen

1. Path: add its pattern to `routePatterns` and a builder function in `src/routes/paths.ts`, with a test. A path that is also an API read (`/projects`, `/runs/{id}/diff`) would be answered with JSON on a reload: put the screen under `/app/` or in a query string, or add the path to `consoleDeepLinkPatterns` in `internal/api/server.go`.
2. Folder: `src/features/<name>/` with `<Name>Screen.tsx` (thin: hooks and components), its components (one per file), and tests beside them.
3. Route: one `<Route>` line in `src/app/App.tsx`; a navigation entry in `src/shared/shell/AppShell.tsx` if it is a top-level screen.
4. Data: use the hooks in `src/api/*Queries.ts`. A screen never calls `fetch` or builds a query key.
5. Tests: `renderApp(<NameScreen />, { server: [...], path, pattern })`. Assert by role and name, and assert what was sent with `server.sent("POST /...")`.
6. Walk: a `step(...)` in `test/walk/walk.mjs` that opens the screen and performs each of its actions.

## Add an API route

| Step                         | Where                                                                                                                                                                                                             |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The Go handler and its route | `internal/api/server.go` (and the operator docs the repository's `AGENTS.md` names)                                                                                                                               |
| A fixture of its response    | One line in `contractRoutes()` in `internal/api/contract_fixtures_test.go`, then `FACTORYD_UPDATE_GOLDEN=1 go test ./internal/api -run TestConsoleContractFixtures`. The test fails until every GET route has one |
| The type and decoder         | `src/domain/<resource>.ts`: `interface X` and `decodeX(o, at)`, with a test that decodes the fixture                                                                                                              |
| The call                     | `src/api/<resource>.ts`: `getX(http, ..., signal)` naming the token kind its handler checks (`read`, `start`, `override`, or `gate` for a request write), with a test of the exact request it sends               |
| The hook                     | `src/api/<resource>Queries.ts`: a query (key from `queryKeys`) or a mutation that caches the answer and invalidates what it changed                                                                               |

## Projects

`features/projects/` is the one place for a project's figures, kill switch,
trend, observations and memory. `/ops` and `/projects/:project/<page>` only
redirect here, so an old link or bookmark still lands. The command to start a
worker is on Mission Control's health strip whenever the worker is not alive.

| Part      | Source                                                                                                 | Rule                                                                                                                                                                                                                                                                                                            |
| --------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Row       | `GET /projects`, plus each project's `/stats` and `/release` (`useProjectRows`)                        | Project, Workspace, Runs, Accepted (`acceptedText` in `domain/project.ts`), Kill switch, Last run. A failed read is isolated to its row; a release read whose latest try failed is "unknown", never "clear" (even after an earlier success), and a failed stats read is a dash titled "Stats could not be read" |
| Details   | `ProjectDetails` (in `ProjectRowDetails` under a row, in `ProjectUnlistedPanel` for an id with no row) | Tabs Stats, Release, Trend, Observations, Memory; a tab's panel reads from the server only while it is selected                                                                                                                                                                                                 |
| Lookup    | `ProjectLookupForm` in the page header                                                                 | "Open a project by id": navigates to that id's Release tab. A kill switch can be engaged before a project's first run, so an id the list does not hold must still be reachable                                                                                                                                  |
| No runs   | `ProjectUnlistedPanel`                                                                                 | `?project=<id>` naming no row opens a panel above the table, "No runs recorded for this project.", with the same tabs and a Close that clears the query; a failed read shows its error there                                                                                                                    |
| URL       | `?project=<id>&tab=stats\|release\|trend\|observations\|memory` (`projectsPath`)                       | Which row is open and which tab is selected, written with `replace`. An absent tab is Stats; an unknown tab is ignored; with two rows of one id only the first opens                                                                                                                                            |
| Redirects | `app/ProjectTabRedirect.tsx`, `routePatterns` in `routes/paths.ts`                                     | `/projects/:project/stats\|release\|observations` open that project on that tab; `/ops` opens the list                                                                                                                                                                                                          |

## Browser notifications

An open console tab raises a Web Notification when a request starts waiting
on the operator; a click focuses that tab and opens the request's page. A
notification carries text and that one click, never an action or a token.

| Part              | Source                                                                                                                                                  | Rule                                                                                                                                                                                                                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What is news      | `last_notified_at` of each request (`domain/attention.ts`, `attend`)                                                                                    | A later time than the one this tab recorded raises one, when it is also after the time this tab answers from: its last look (`watchingSince`, kept across a reload in session storage), or 20 seconds before it took over as the notifier. The comparison is against this browser's clock |
| What it says      | `last_ask` (title, with a fallback), project and title (body), `<id>:<last_notified_at>` (tag)                                                          | `notificationContent`: a second tab raising the same notification replaces it; a later reminder alerts again                                                                                                                                                                              |
| Which tab raises  | `platform/browserNotifications.ts`: the Web Lock `buildgate-notifier`                                                                                   | One tab per browser holds it for as long as it lives. Without Web Locks every tab raises, and the tag de-duplicates at the OS                                                                                                                                                             |
| When a tab is it  | `shared/shell/useBrowserNotifier.ts`                                                                                                                    | Permission granted, the switch on (`factoryBrowserNotifications` in local storage), and the lock held                                                                                                                                                                                     |
| Where it listens  | `useNotifierStream` (`api/requestQueries.ts`), held by the shell on every screen while this tab is it; the list the shell polls (`useRequests`) besides | Every tab records what it has seen, and a tab that takes over the lock raises only what was sent from 20 seconds before                                                                                                                                                                   |
| The stream flag   | `watchRequests(..., { notifier: true })`, only from `useNotifierStream`                                                                                 | `GET /requests/events?notifier=1`: while a tab on the host holds it, the server holds back the host's own banner                                                                                                                                                                          |
| The switch        | `shared/shell/NotificationToggle.tsx`, in the sidebar footer                                                                                            | Absent without the API; "Turn on notifications", "Notifications on", or a note that the browser blocks them                                                                                                                                                                               |
| Opening a request | `requestPath` in `routes/paths.ts`, through the router                                                                                                  | The click handler runs `window.focus()`, navigates, then closes the notification                                                                                                                                                                                                          |

## Comments on passages

At `spec_review` and `plan_review` a reader selects text in a spec or ticket
file's raw view and comments on it; the comments are sent together by
"Request changes", and the redraft changes only the sections they are on.

| Part              | Source                                                                                                | Rule                                                                                                                                                                                                     |
| ----------------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The selection     | `features/request-detail/FileContentSection.tsx`, `PassageComposer.tsx`                               | Only in the raw view, where the shown text is the file's text; a selection that is not plain text of the file cannot be placed and says so                                                               |
| Where it lands    | `anchorForSelection` in `domain/reviewAnchors.ts`                                                     | The nearest required heading above it, the numbered criterion it starts in, and the selected text as the quote (cut at its section, 2000 bytes)                                                          |
| The pending batch | `platform/pendingComments.ts`, `features/request-detail/usePendingComments.ts`, `PendingComments.tsx` | Per browser, keyed by request id and the time it entered the stage, so a redraft starts with none; listed under the oracle warning, removable one by one                                                 |
| Sending it        | `shared/approval/RejectDialog.tsx`                                                                    | "Request changes (N)" opens the dialog with the batch as its notes. A reason written too asks the server for a whole redraft; the server refuses (409) a comment whose quote is no longer in its section |

## Read-back at spec review

A spec the operator handed over (`submit -spec-file`) reaches `spec_review`
with the factory's read-back: what it will build and the questions it would
otherwise guess at. The page shows it beside the spec as model-written text.

| Part         | Source                                                                                      | Rule                                                                                                                                                                                                                                                               |
| ------------ | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| The panel    | `features/request-detail/ReadBackPanel.tsx`, from `StageSection`                            | Only at `spec_review` with a drafted read-back; the summary and each question as text, never HTML. A read-back that could not be drafted is a review note instead                                                                                                  |
| An answer    | `useAnswerReadBack` (`api/requestQueries.ts`), `answerReadBackQuestion` (`api/requests.ts`) | One answer box and Save per question: `PUT /requests/{id}/read-back/answers/{qid}` with the SHA-256 of the question text shown; empty clears it. Disabled without write access; at most 2000 bytes. A box starts over when its stored answer changes underneath it |
| Approval     | `expectedSha256For` (`domain/contentHash.ts`), `useRequestDialogs`, `ApproveDialog`         | A spec approval sends `readBackAnswersSha256` of the answers shown under `read-back/answers`; Approve warns about a box with unsaved text. The answer log is in the Audit panel                                                                                    |
| What it does | The server                                                                                  | Answers are frozen at approval and go to every ticket's build; approval never waits on them                                                                                                                                                                        |

## Module layout

```text
src/
  domain/     pure TypeScript: types, decoders, formatting and rules. No React, no I/O
  api/        the only code that talks HTTP: one file per resource, query hooks, SSE
  platform/   the only code that touches browser globals (storage, location, title)
  routes/     the route table and typed link builders: every path is written here once
  ui/         shared presentational components. No data fetching
  shared/     components more than one feature uses that fetch or write data
              (the approve/reject dialogs, the oracle panels, the app shell)
  features/   one folder per screen area: its screen, local components, hooks, tests
  app/        App, router wiring, providers
  test/       test setup and fixture readers
```

```text
app ──> features ──> shared ──> ui ──> domain
           │           │
           │           ├──> api ──────> domain
           │           ├──> routes ───> domain
           │           └──> platform ─> domain
           └──> (also ui, api, routes, platform directly)
features/X never imports features/Y: navigate with a routes/ link builder, and
move what two features both need into shared/
domain imports nothing outside domain
```

`eslint.config.js` enforces every arrow, so a violation fails `npm run lint`.
It also bans `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `fetch` outside
`api/`, and `localStorage` outside `platform/`.

## Conventions

| Topic            | Rule                                                                                                                                                                                                                                                                               |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Imports          | Across directories, through the `@/` alias (`@/domain/run`). Relative (`./x`) only inside one directory. No `../`                                                                                                                                                                  |
| Exports          | Named exports only. No default exports, no barrel `index.ts` files                                                                                                                                                                                                                 |
| Types            | `interface` with `readonly` fields for data. No `any`; `unknown` plus a decoder at the edge. No enums: a union of string literals, and `string` for a server-owned set that can grow (states)                                                                                      |
| Decoders         | One per API shape, in `domain/`, written with `domain/decode.ts`. `decodeX(o: JsonObject, at: string): X`. Required fields throw with the route name; optional fields take a fallback; unknown fields are ignored. Field names are camelCase in TypeScript, snake_case on the wire |
| Absence          | `null` for "not known" (never `undefined` in a decoded type); `""`, `0`, `false`, `[]` where Go omits a zero value                                                                                                                                                                 |
| Pure logic       | Lives in `domain/`, as functions over domain types, with a unit test beside it. Time is a parameter (`now: Date`), never read inside                                                                                                                                               |
| Components       | Function components. Props typed with an `interface XProps`. One component per file, named as the file. A screen composes hooks and components; logic over 20 lines moves to `domain/` or a hook                                                                                   |
| Data fetching    | Only through the hooks `api/<resource>.ts` exports (`useRun(id)`, `useApproveRequest()`). Query keys and invalidation live there; a screen never builds a key                                                                                                                      |
| State            | Server state in TanStack Query. Local UI state in `useState`/`useReducer`. No global store                                                                                                                                                                                         |
| Untrusted text   | Specs, logs, halt reasons and diffs are agent-written. Render as text or through `ui/Markdown`; never as HTML                                                                                                                                                                      |
| Styling          | Tailwind utility classes and the design tokens in `app/styles.css`. Variants with `class-variance-authority`; merge classes with `ui/cn`                                                                                                                                           |
| Accessible names | Button, link and heading names are stable: the walk finds controls by them                                                                                                                                                                                                         |
| Tests            | Beside the code as `x.test.ts(x)`. Vitest globals, Testing Library, queries by role and name. Expected values are written out, not computed by the code under test                                                                                                                 |
| Comments         | Say why. Keep a rule's origin where it came from a found bug; no changelog narration                                                                                                                                                                                               |

## Visual language

The console is a dense tool for engineers: dark by default, light on request,
quiet surfaces, colour reserved for state.

| Topic        | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Colour       | Only the semantic names of `app/styles.css`, in three layers: a per-theme ramp (eleven neutral steps `--n1`..`--n11`, the text-control fill, accent, tone and diff values), the role names that point at it (`bg-bg`, `bg-surface`, `bg-surface-raised`, `bg-surface-sunken`, `bg-surface-hover`, `border-border`, `border-border-strong`, `text-fg`, `text-fg-muted`, `text-fg-subtle`), and the Tailwind names. Text controls use `border-border-control` and `bg-field`. Also `bg-accent`, `text-accent`, `bg-accent-soft`, `text-tone-*`, `bg-tone-*-soft`, `border-tone-*-border`, `bg-diff-*`. Never a palette colour (`bg-zinc-900`), never a hex value, never a `dark:` variant: the ramp changes with the theme. Tones: amber waits on the operator, teal the factory is working, green passed, red failed or stuck, grey idle or unknown. Blue is only for what can be pressed |
| State colour | A request, run or PR state is drawn from `domain/status` (`statusForToken` -> `statusTone`) through `ui/tone.ts`. Nothing else picks a colour for a state                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Type         | Five sizes, in pixels so the 14px root does not shrink them: `text-xs` 12 (meta, table headers), `text-sm` 13 (body, card titles, controls; `font-semibold` for a title in a card), `text-base` 16 (section and dialog headings), `text-lg` 20 (page title), `text-xl` 24 (a large figure). IDs, SHAs, paths, commands, logs, diffs and token counts are `font-mono`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Density      | The root is 14px, so a spacing step is 3.5px. Controls are 24.5px and 28px high (`h-7`, `h-8`), table rows 31.5px (`h-9`). Card padding `p-4`; page gutter `px-6 py-5`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Shape        | `rounded-md` controls, `rounded-lg` cards and dialogs, 1px `border-border`. Cards carry a hairline shadow (`shadow-card`) in the light theme and none in the dark; popovers and dialogs use `shadow-popover`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Icons        | `lucide-react`, drawn at 14px (`size-4` on the 14px root), `aria-hidden` beside a text label. One shape per state family, named as lucide names it: `circle_alert` waits on the operator, `circle_dot` in progress (the factory is working), `circle_check` passed or done, `circle_x` failed, `circle_help` unknown, `triangle_alert` stalled or a warning, `circle_check_big` confirmed clear, `octagon_pause` stuck (the factory cannot move it), `circle_dashed` not started, queued or connecting, `circle_minus` skipped, `hourglass` waiting its turn. The map is `ui/statusIcons`, read by the chip and the timeline. `RefreshCw` is only an action (refresh, reload, retry). An icon-only button is a `ui/IconButton`: its `label` is its `aria-label` and its tooltip. The external-link icon is only on a link that leaves the console                                        |
| Motion       | Motion only for a change the operator caused, a change that just happened, or work that is live. What moves: `transition-colors`; a disclosure chevron; an overlay's 120ms fade on open (dialog, menu, tooltip); a board card's 1.5s highlight when its state changes while the screen is open; a spinner (`Loader2`) for live work (a running stage of a run that is not stalled and whose feed is connected; the board card and health-strip entry of a request the worker is running now; a pending request the operator just made); a loading spinner or skeleton. Everything stops under reduced motion (`motion-reduce:animate-none`, the spinner is drawn still). Nothing else moves: no entrance animation, stagger, count-up, pulse on a static status, or hover lift                                                                                                           |
| Emoji        | None in anything the console draws; text a person or an agent wrote is shown as written                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Overload     | A passing step is one line; a failure opens itself and sorts first. A block with nothing in it is absent, never "None" or "Not available". Closed detail is a `ui/Disclosure` with a one-line summary. An age is `ui/RelativeTime` everywhere (relative, exact time on hover); where the time itself is the information (audit lines, decision and rejection history, the release panel) it is the exact local time with its UTC offset, `2026-09-10 04:06:00 -05:00` (`formatLocalTimestamp`). A raw ISO string is never shown. Long machine text is `shared/request/DigestedText`: first sentence, the whole one click away. What an approval is bound to (spec, plan, oracle files in a review state) is never folded or cut                                                                                                                                                          |
| Paths        | Workspace, project, log, spec and ticket-plan paths are shown in full and wrapped to fit. Copy controls use the complete absolute path on the serve host (`ui/PathValue`, `FileContentSection`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Copy         | Anything an operator would paste into a terminal (a command, an id, a branch, a path, the address of a link that leaves the console) has a copy button beside it (`ui/CopyButton`; `ui/TextWithCode` adds one to every code span, `ui/CompactId` and `ui/PathValue` to ids and paths). Ordinary text must be one line of printable ASCII (`pastesAsShown`); filesystem paths may also contain visible Unicode (`pastesPathAsShown`). Both reject hidden/control characters and ambiguous whitespace                                                                                                                                                                                                                                                                                                                                                                                      |
| Focus        | Never remove the focus ring (`:focus-visible` is styled globally)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Primitives   | Dialog, Tabs, Tooltip and DropdownMenu wrap the Radix primitive of the same name: it supplies focus trapping, keyboard handling and ARIA                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Components   | `class-variance-authority` for variants, `ui/cn` to merge a `className` prop, which every component accepts last. `ui/Button.tsx` is the pattern to copy                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

### Where a change goes

| Change                           | Touch                                                                                                                                                                                        |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A theme                          | One block of ramp values in `app/styles.css` plus one entry (name, scheme, block) in the theme list of `app/tokens.test.ts`; choosing it at run time is `platform/themeStore` and the toggle |
| A status icon                    | One entry in `ui/statusIcons` and its name in `domain/status.ts`'s `StatusIcon`                                                                                                              |
| A state's icon or tone           | `domain/status.ts`                                                                                                                                                                           |
| A board group                    | Its rule in `domain/boardColumns.ts` (match order, draw order, one-state flag)                                                                                                               |
| A state's label or a verb's word | `domain/status.ts` (`REQUEST_STATES`, `REQUEST_VERBS`); every screen reads them from there                                                                                                   |
| A detail page's header           | `ui/PageLayout` `PageHeader` (back link, title, chip row, actions); the request and run pages are the pattern                                                                                |
