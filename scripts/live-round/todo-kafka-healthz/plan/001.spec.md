## Goal

Add the dependency-free `/healthz` liveness endpoint to the package `main` root API, with a synchronous JSON success response for GET and a method-not-allowed response for every other method, while leaving all dependency initialization and existing routes unchanged.

## Plan

### Files to touch

- `main.go` — add the health handler and register the exact `/healthz` path on the existing root `http.ServeMux`.
- `main_test.go` — add table-driven handler coverage and a root-mux registration check that run without external services.

### Steps

1. Add a `handleHealthz` handler in `main.go` that rejects any request whose method is not `GET` with HTTP 405 before doing any other work.
2. For GET requests, have the handler synchronously write the constant JSON object with only the `status` field set to `ok`, using the existing JSON response helper so the response has `Content-Type: application/json`; do not read or call Postgres, Kafka, Redis, or any application dependency.
3. Register `"/healthz"` beside the existing root API routes in `registerRoutes`, without adding a prefix, trailing-slash variant, dependency wiring, or startup behavior.
4. Add a table-driven handler test in `main_test.go` covering GET and the non-GET methods HEAD, POST, PUT, PATCH, DELETE, and OPTIONS. Assert GET returns 200, the application/json content type, and a decoded object containing exactly `status: "ok"`; assert each non-GET returns 405 without configuring or invoking any external dependency.
5. Add a root-mux route test that builds a fresh `http.ServeMux`, calls `registerRoutes`, and sends `GET /healthz`, proving the exact root path reaches the new handler rather than a 404 or an existing todo route while no dependency-backed state is configured.

### Tests to add

- A table-driven `main_test.go` test for the health handler's JSON GET response and all required non-GET 405 responses.
- A `main_test.go` route-registration test using a fresh root mux and `GET /healthz`, with no Postgres, Kafka, or Redis setup.
