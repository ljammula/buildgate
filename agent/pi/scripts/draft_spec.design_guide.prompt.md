## Team design guide: spec decisions

The team that owns this repository wrote the guide between the markers
below. Answer each of its questions for this request, and state each
answer with its reason in the section of the spec it changes, usually
Scope; an answer that changes what a caller observes also becomes an
acceptance criterion. Follow the guide's rule for a question unless the
request itself says otherwise. When the guide leaves a choice to the
operator, or its rule does not settle a high-impact choice, write that
choice as a `[NEEDS DECISION]` item under Open questions. Do not add
infrastructure the guide's answers do not call for. The guide adds
decisions to consider; the drafting rules that follow still apply in full.
