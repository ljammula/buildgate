Report only concrete correctness, security, data-loss, or concurrency defects. Before reporting one, inspect the relevant implementation and trace the triggering input or state through its actual control flow to the observable wrong result. Check the types, function contracts, call sites, and error handling that determine that behavior; account for every relevant return value and branch instead of inferring semantics from a name or one value alone. A concern that depends on an assumption you cannot verify from the repository is not a finding.

Each finding must describe a concrete failure scenario: the input or state that triggers it, the code path it takes, and the wrong result it produces. Do NOT report style, formatting, naming, lint, or missing-comment issues -- those are not this review's concern and must never appear as a finding.
